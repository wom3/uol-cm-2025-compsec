Recommended fix
Sensitive credentials (e.g. passwords) stored in plain text within configuration files
Secure storage/avoid hardcoding secrets
Credentials may be leaked via source control or deployment leading to unauthorised system access.
Use environment variables or secrets management tools to store credentials securely outside the codebase.
Uploaded files saved using user-supplied filenames in publicly accessible directories
File upload controls/sanitisation/least privilege
Attackers could upload disguised malicious files (e.g. scripts) and trigger execution via public URLs.
Rename uploads with server-generated names, restrict execution rights, store in non-public folders and scan files on upload.
SQL queries constructed by directly appending user input
Input validation
Vulnerable to SQL injection; attacker could view, alter or delete data.
Use parameterised queries and validate all user inputs on the server and client side.
Application displays details error messages with stack traces
Fail securely/information exposure
Attackers gain insights into system internals (e.g. file paths, code logic), increasing attack precision.
Log full errors internally; display only generic user-facing messages like ‘An error occurred.’
